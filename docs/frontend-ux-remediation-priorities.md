# 前端可理解性与视觉一致性改造清单

> 来源：2026-07-22 前端全路由、关键动态文本与桌面/手机端审查。
>
> 范围：八字排盘、日/周/月运、紫微、卜易、出生信息、账户与历史页。
>
> 原则：面向普通用户，用人话说明“这是结构参考而不是现实结果”；不展示内部状态、枚举、研究术语或未经解释的精确分数。改动不需要保留旧界面兼容层。

## 优先级定义

| 优先级 | 含义 | 处理目标 |
| --- | --- | --- |
| P0 | 误导性强、可能造成伤害，或直接破坏核心产品可信度 | 本轮优先修复并验收 |
| P1 | 普通用户明显看不懂、信息自相矛盾、核心流程受阻 | P0 后紧接着处理 |
| P2 | 层级、文案、可读性与视觉一致性问题 | 结合页面重构集中处理 |

## P0：先恢复可信度与基础视觉

### 1. 移除“吉凶评分”的伪精确表达

**现象**

- 日运、周运、月运使用 0–100 分、正负“影响值”、趋势图和“最终值”，视觉上像经过验证的预测指标。
- 后端数据实际标注为 `not_validated`、`not_adjudicated`，且权重来自本地启发式规则；这些关键信息没有与数字同时展示。
- “关系活跃度”实际是带正负倾向的加减分：关系更多的日期可能分数更低，却被周/月页面称为“关系较少日”。
- `supporting_evidence` 只是正分项集合，页面却将“日主克流日”等内容归到“生扶关系”，分类本身不成立。
- 卜易把随机结果与关键词加减分包装成“吉凶评分”。

**影响**

用户会把结构对照或随机结果理解为可验证的事件概率、吉凶结论，直接损害产品可信度。

**建议**

1. 将“分数 / 最终值 / 影响值”统一改为“关系变化参考”或仅保留相对关系标签。
2. 若保留按关系数量的描述，必须基于实际关系条数，而不是正负权重后的分数；“生扶 / 冲克”按真实关系类型归类。
3. 如保留数值，数字旁固定显示“本地规则权重，未验证；不代表事件概率或吉凶”。
4. 在普通模式隐藏精确权重；“推算”模式必须先说明权重来源、适用边界和未验证状态。
5. 卜易取消“评分”及任何强结论，把结果明确为“随机抽取的传统文本参考”，并移除危险、歧视、绝对化原文。

**涉及位置**

- `vue/src/views/FortuneView.vue`
- `vue/src/components/FortuneEvidencePanel.vue`
- `vue/src/views/WeeklyFortuneView.vue`
- `vue/src/views/MonthlyFortuneView.vue`
- `vue/src/views/BuyiView.vue`
- `src/internal/service/fortune/score_pipeline.go`
- `src/internal/service/buyi/buyi.go`
- `src/internal/service/buyi/data.go`

**验收**

- 任何数值旁均可在一眼内看到其性质与限制。
- “关系较多 / 较少”与实际命中的关系数量一致；“生扶 / 冲克”不再按加减分错误归类。
- 页面不再使用“吉凶评分”“命运倾向”“现实结果”等确定性表述。
- 卜易结果不再包含伤害、歧视或恐吓性建议。

### 2. 清理仍然突兀的近黑实底卡片

**现象**

经典依据面板的外层是暖色玻璃卡，内部段落却使用 `--surface-0` 的近黑实底；在手机端会连成大块黑色区域，与项目的暖色、半透明风格割裂。

**建议**

1. 将内部段落卡改为与外层同体系的半透明暖色表面，使用细边框或间距建立层级。
2. 只保留一个主容器阴影；内部卡不要再叠加厚重黑底。
3. 统一“内容卡 / 证据卡 / 反馈区”的背景色 token，避免各组件自行使用最深色表面。

**涉及位置**

- `vue/src/components/ClassicalInterpretationPanel.vue`
- `vue/src/components/BaziChart.vue`
- `vue/src/components/DailyFortune.vue`
- 全局主题 token：`vue/src/style.css`

**验收**

- 390px 手机端不出现连续、抢眼的纯黑内容块。
- 主信息、次级信息、可操作区的层级由间距、边框和透明度建立，而不是由黑色填充建立。

### 3. 经典依据与规则摘要必须明确区分

**现象**

当检索功能未启用时，页面状态写“经典依据暂未启用”，但标题仍为“八字经典参考”，并显示规则生成的三段内容、`重新生成` 按钮及“准/不准”反馈。用户无法知道是否真的有典籍引用。

**建议**

1. 有可用引用时才使用“经典依据 / 典籍引用”名称。
2. 降级状态改为“规则摘要（暂无典籍引用）”，并说明内容来源于当前命盘规则。
3. 将“重新生成”改为“重新加载”或“重试检索”；功能禁用时隐藏该按钮。
4. 没有引用时不要把段落反馈包装成“准确性研究”。

**涉及位置**

- `vue/src/components/ClassicalInterpretationPanel.vue`
- `src/internal/service/interpretation/bazi.go`

**验收**

- 用户能明确分辨“规则摘要”“检索到的典籍引用”“检索不可用”三种状态。

## P1：消除核心页面的误解与流程障碍

### 4. 重写经典解读反馈的措辞和授权说明

**现象**

接口契约限定为“解读质量，不是结果准确率”，界面却让用户选“准 / 不准”，复选框称“允许用于内部解读准确性研究”。

**建议**

1. 将选项换为“清楚”“有帮助”“依据不足”“过于笼统”“看不懂”。
2. 授权文案改为“允许将这条匿名的内容质量反馈用于改进规则说明”，并补充收集内容与退出方式。
3. 明确“不用于判断现实事件是否发生，也不用于预测准确率”。

**涉及位置**

- `vue/src/components/ClassicalInterpretationPanel.vue`
- `vue/src/api/feedback.ts`
- `src/internal/model/fortune_feedback.go`

### 5. 把内部术语、枚举和研究语言隔离在开发侧

**现象**

- 紫微页面出现 `MALE`、GitHub 来源、`Profile`、PDF 页码、“待裁决”“合同内裁决”等内部文本。
- 八字总览显示 `day/hour/month/year`。
- 日课关系使用“查询干生目标干”“目标干克查询干”等机器式名称。
- 月令状态裸露“死”，没有说明这是传统季节强弱标签。
- 八字关系会把 `month_to_day` 等方向代码、`Profile`、规则 ID、流水线和版本信息混进面向用户的正文。
- 多个页面直接显示后端英文错误，例如 `chart not found`、`invalid username or password`。

**建议**

1. 建立前端展示映射：`MALE/FEMALE` → “男/女”，字段 key → “年柱/月份/日柱/时柱”。
2. 将“未裁决”类内容替换为“仅作结构记录，不推断现实结果”；删除合同、Profile、源码、PDF 等开发/研究信息。
3. 日课关系改为以两端对象说人话，例如“今日天干生助日主”。
4. 对“旺、相、休、囚、死”增加简短释义，并把“死”改为“弱势（传统季节标签）”等避免误读的表述。
5. 建立统一的错误码 → 中文说明 → 恢复动作映射；不得将后端原始错误直接显示给用户。

**涉及位置**

- `vue/src/views/ZiWeiView.vue`
- `vue/src/components/ZiWeiInterpretation.vue`
- `vue/src/components/ZiWeiOverlay.vue`
- `vue/src/components/BaziChart.vue`
- `vue/src/components/DailyFortune.vue`
- `src/internal/service/fortune/fortune.go`

- `src/internal/service/ziwei/ziwei_knowledge.go`
- `src/internal/service/bazi/gan_relation_graph.go`

- `vue/src/api/client.ts`

### 6. 出生时间不确定时提供可理解的候选盘决策

**现象**

后端已返回交界原因、稳定字段和变化字段；前端只显示“候选 1/2”和两套四柱，要求用户盲选。

**建议**

1. 先解释“为什么会出现多个候选盘”（时辰交界、子初换日、立春等）。
2. 显示每个候选盘的实际时间区间及“哪些柱会变化”。
3. 提供选择建议：以出生证明/家人记录为准；无法确认时保留候选并在结果中持续标识。
4. 真太阳时提示先给结论，再折叠 `USNO J2000`、`UTC/UT1` 等专业细节。

**涉及位置**

- `vue/src/components/BirthInputForm.vue`
- `src/internal/service/bazi/uncertainty.go`
- `src/internal/service/bazi/birth_input.go`

### 7. 修正日运、周运、月运的层级和行动入口

**现象**

- 缺命盘、网络错误、无数据时的下一步不一致或不可操作。
- 日运仍显示“星象推演中”“深度解析·规划中”等无行动价值占位。
- 周运只有数值、雷达和曲线，没有普通用户可读的周结论。
- 月运虽然有总述，仍主要复述“离散度、旬均值、指数极值日期、末值较高/较低”。

**建议**

1. 各状态统一提供：错误原因、重试、去排盘或返回上一页。
2. 删除“规划中”等占位；未开放内容直接不显示或说明开放条件。
3. 周/月页面先给“本周期结构概览”和“建议先看哪一天/哪一段”，统计指标移入详细模式。
4. 统一使用“关系活跃度”，不再混用“结构指数”。

**涉及位置**

- `vue/src/views/FortuneView.vue`
- `vue/src/views/WeeklyFortuneView.vue`
- `vue/src/views/MonthlyFortuneView.vue`
- `vue/src/components/fortune/DayFortuneCard.vue`
- `vue/src/components/fortune/FortuneHeatStrip.vue`
- `vue/src/components/FortuneChart.vue`

### 8. 修正基础模式“计数和内容不一致”

**现象**

简明模式只渲染每类关系的前两条，但标题仍显示完整条数；例如存在 3 条生扶关系时，界面显示“3 条”却只看到 2 条。

**建议**

显示“已展示 2/3 条”，并提供“查看全部关系”入口；或在简明模式只显示“重点关系”而不显示总数。

**涉及位置**

- `vue/src/components/FortuneEvidencePanel.vue`

### 9. 修复历史与账户表单的基础可用性

**现象**

- “运势历史”实际跳转到今日运势。
- 性别直接显示 `MALE/FEMALE`。
- 注册页没有在输入前说明密码至少 8 位；失败信息不够具体；显示密码按钮缺少无障碍名称。

**建议**

1. 历史入口跳转到对应历史记录，并使用中文性别标签。
2. 密码字段下直接显示规则；将后端校验错误翻译为可行动提示。
3. 为密码可见性按钮增加 `aria-label`，并同步显示当前状态。

**涉及位置**

- `vue/src/views/HistoryView.vue`
- `vue/src/views/RegisterView.vue`

### 10. 修正“今日五行”和月运占比的口径

**现象**

- “今日五行”实际取查询日中午 12:00 的四柱并按固定权重累计；页面没有说明时间基准、单位和计算口径，柱状图与数字又使用不同单位。
- 月运把 `0.3978` 直接标成“五行占比”，而不是 `39.78%`；“火主气”容易被误读为月令旺衰，实际只是样本累计频次最高。

**建议**

1. 默认改为“当日中午样本的五行结构参考”，或隐藏该模块，直到能够提供更符合用户预期的全天口径。
2. 统一图形和文本的单位，百分比必须按百分号格式化。
3. 将“主气”改为“样本中出现较多的五行”，并提供简短口径说明。

**涉及位置**

- `vue/src/components/DailyFortune.vue`
- `vue/src/views/MonthlyFortuneView.vue`
- `src/internal/service/fortune/fortune.go`

### 11. 修正出生信息的日期、校验和无障碍关联

**现象**

- 紫微农历命盘会把农历输入日直接标成公历日期，且“农历生日”只是固定文本；后端已有正确转换值但前端未使用。
- 无效日期、无效农历、时区歧义、夏令时重复时间和经度越界等具体错误被统一压成“校验失败，请检查出生信息”。
- 年、月、日、小时等标签没有通过 `for/id` 或 `aria-label` 关联输入框，读屏软件只能读到无名称的数字输入框。

**建议**

1. 公历、农历输入与转换结果分别显示，并以数据来源决定标签，禁止用原始数字冒充转换后的日期。
2. 保留后端可行动的校验原因，并定位到相应字段；只对未知错误使用通用兜底。
3. 为每个出生日期、时间、地点和时区控件补齐可访问名称与错误关联。

**涉及位置**

- `vue/src/views/ZiWeiView.vue`
- `vue/src/components/BirthInputForm.vue`
- `vue/src/api/client.ts`
- `src/internal/service/bazi/birth_input.go`

### 12. 重构紫微四化与规则来源的展示模型

**现象**

- 四化页一次展示 4 条本命四化和 48 条宫干飞化，接近原始数据转储；没有摘要、阅读顺序、筛选或解释“源命宫 / 跨宫 / 自化”。
- “本命年干四化”与“十二宫宫干飞化”混在同一层，用户无法辨别两者的来源和用途。
- 闰月、流曜、格局等不同来源被一律标成“亮度来源”，属于事实分类错误。

**建议**

1. 默认只展示四项本命四化摘要及“如何阅读”的说明；宫干飞化按来源宫位折叠，并支持筛选。
2. 每类规则在首项说明“由什么计算、仅表示什么、不能表示什么”。
3. 使用正确的来源分类，不能把所有计算来源写成亮度来源。

**涉及位置**

- `vue/src/views/ZiWeiView.vue`
- `vue/src/api/ziwei.ts`
- `src/internal/service/ziwei/ziwei_knowledge.go`
- `src/internal/service/ziwei/profile.go`

### 13. 重新定位“运势加持”模块

**现象**

- 该页的大部分建议按当天五行套用前端静态模板，不随用户命盘变化，却在入口和文案中呈现为个性化命理建议。
- 未裁决的冲克关系被直接提升为“今日慎行”，移除了日运页原有的边界说明。
- “静驻时间”打开页面便自动增长，实际是页面停留时间；“感应、承气、气场”等措辞又强化了超自然效果暗示。
- 390px 手机端内容超过五屏，建议重复且末尾展示全部静态模板。

**建议**

1. 重命名为“今日行动灵感”或在入口明确说明“按当天五行生成的通用生活建议，不是新的个性化排盘结果”。
2. 将“今日慎行”改为“可留意的关系记录”，保留非事件结论边界；没有验证依据时不生成行为建议。
3. 计时器改为用户显式开始/暂停的“练习计时”，或直接删除。
4. 移除神秘化承诺，合并重复内容，默认只展示当前主题的一组建议。

**涉及位置**

- `vue/src/views/FortuneBlessingView.vue`

### 14. 让“普通 / 详细 / 推算”真正兑现层级承诺

**现象**

- “简明·重点关系”只给专业术语，没有白话解释。
- “详细·原因与依据”显示描述但隐藏真实依据。
- “推算·计算过程”暴露内部权重，却没有解释为何采用这些权重或其未验证状态。

**建议**

1. 简明层至少给一条可读解释和下一步阅读提示。
2. 详细层显示中文化依据与来源，而不是只增加术语密度。
3. 推算层显示规则口径、权重来源和验证状态；内部 ID、版本号、哈希仍不得展示。

**涉及位置**

## P2：完善信息层级、术语说明与手机阅读

### 15. 为紫微首屏和宫位明细减负

**现象**

- 首屏一次展示来源、四化飞星、宫位明细等大量内容。
- 四化飞星可达 48 条，辅煞使用机器缩写，部分宫位显示“病/死/墓/绝”。
- 手机上的字号过小，来源列表占据过多首屏空间；命盘还会被缩成左侧极窄区域，右侧留下大面积空白。

**建议**

1. 首屏只保留命盘、关键宫位和简短说明；将来源、飞星全量、计算依据折叠到详细模式。
2. 飞星按宫位聚合，默认展示最相关项目与“查看全部”。
3. 给传统状态术语加解释与非现实结果提示；辅煞显示全称和简要说明。
4. 手机端最小正文保持 14px 以上，避免 8–10px 的信息文本；命盘应占满可用宽度，不得缩成不可读的窄棋盘。

**涉及位置**

- `vue/src/views/ZiWeiView.vue`
- `vue/src/components/ZiWeiInterpretation.vue`
- `vue/src/components/ZiWeiOverlay.vue`

### 16. 重构八字总览的专业信息呈现

**现象**

- “身强 / 身弱”“真实强弱”、百分比等表述太确定；而计算是未验证的候选规则。
- 格局、调候、十神、神煞信息在一个层级连续堆叠。
- 手机端四柱顺序被五行图打断，标签页过多且部分隐藏。

**建议**

1. 将“真实强弱”改为“当前规则下的五行分布参考”，移除或弱化精确百分比。
2. 以“先看什么”为主线重排：四柱 → 五行关系 → 传统参考项；其余收进详细页签。
3. 手机端确保四柱连续出现，提供可横滑且可见的标签导航或改为折叠区块。

**涉及位置**

- `vue/src/components/BaziChart.vue`
- `vue/src/views/ChartView.vue`

### 17. 统一解读层级的名称与边界

**现象**

“简明 / 详细 / 推算”中，“推算”容易被理解成更权威的预测，但其实际内容是本地规则的计算过程。

**建议**

1. 将“推算”改为“规则明细”或“计算说明”。
2. 在切换器下补一行说明：详细程度变化不代表结论可靠性变化。
3. 切换层级时提示被隐藏/新增的模块，避免用户不知道还有内容。

**涉及位置**

- `vue/src/components/InterpretationLevelSwitch.vue`
- `vue/src/components/DailyFortune.vue`

### 18. 控制神煞、黄历和祝福模块的装饰性噪音

**现象**

- 神煞直接输出来源标签和资料定位。
- 黄历、日课与祝福混杂结构记录、传统宜忌和随机文案；“加持”自动计时会放大结果的仪式感。

**建议**

1. 神煞只展示名称、通俗解释和“传统参考”说明，资料定位移到展开的引用区。
2. 黄历与日课分区，说明二者参考对象不同。
3. 将祝福定位为“自我提醒 / 计划提示”；取消随机结果的强暗示和自动仪式计时，或提供关闭入口。

**涉及位置**

- `vue/src/components/BaziChart.vue`
- `vue/src/components/DailyFortune.vue`
- `vue/src/views/FortuneBlessingView.vue`

## 每项改动的验收方式

- 仅运行受影响前端包的验证：`cd vue && npm run build`。
- 对涉及交互的页面，至少手工检查桌面端和 390px 宽手机端：排盘、日运、周运、月运、紫微、卜易、注册。
